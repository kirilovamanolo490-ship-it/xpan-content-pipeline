# 每日八条文案的事实提炼与发送前审阅

本审阅位于媒体准备之后、Telegram 发送和 Typefully 操作之前。`build_telegram_caption.py` 生成的两份文件带 `【待审初稿】`，只用于了解资料；必须结合来源改写并删除标记。每条真实发送或建稿前都要有 `copy-review.json`，并在批次开始外发前核对当前 Excel 简介、完整目录、必要预览、Telegram 与 X 文案。

## 1. 先把来源读明白

同时检查固定工作表该行的完整标题、文字介绍、新夸克链接，以及 `output/assets/{序号四位数}/telegram-project-details.json` 的完整 `items` 文件树。不能只看 `representative_files`、分享页首屏或视频首帧。简介若是“待转存后补充”等占位文字，不当作事实。已有 `copy-review.json` 的 `source_note` 若记录了同版本官方说明、实际书页或压缩包内部目录，也应复核并利用这些补充证据，不能只看外层文件名又全部退回“未知”；公开文案本身不是来源证明。文件名不足以支持具体功能、方法或收入判断时，继续查看真实预览或官方一手说明；仍不足就缩窄主张，并把依据和限制写进 `source_note`，不要把“目录能确认”“只核到封面”“未核实”等工作过程写进正文。

动笔前在审阅记录中梳理：

1. 题材与最能吸引目标读者的具体用途或优势。
2. 主卖点，以及来源支持的相关好处、步骤、烦恼或应用场景。围绕它把价值讲透；不要只扔一个噱头，也不要把整个目录逐项搬进正文。
3. 至少一个完整文件树中确实存在的文件名或相对路径。商业类优先找项目介绍、实操、获客、成交、交付、回填链接等证据。
4. 商业路径：做什么或卖什么、谁可能付钱、如何成交和交付、钱从哪里来。证据只覆盖制作端时，记录收入环节尚未证实以及支持程度，不要把标题中的收益数字、“躺赚”或“零门槛”当结果。
5. 影响读者判断的重要限制，例如工具功能没有亲自实测、收入案例只是资料方标注、平台规则可能变化。限制留在审阅记录；仅当它是读者安全或决策所必需时，才用简短自然的话写进正文。

例如：写作资料若有投稿和过稿内容，可以讲选题、成稿、投稿到稿费的路径；付费社群源码可以讲内容承接到付费进群的做法；只有角色设计和作图课程的 AI 漫剧资料，就讲制作能力，不把标题里的月收入说成已验证成果。赚钱相关内容要说明具体做什么、谁付钱、成交与交付怎么发生；只能确认其中一段时如实限定。

## 2. 两个渠道分别写，自然说人话

两边共享已核实的关键事实，但表达可按渠道调整，不必复制粘贴。整体像路边碰见朋友时直接聊到一个有意思的东西：先说具体用途、优势或反常识之处，再把来源支持的相关好处讲清楚。可以使用“我靠”“牛逼”“真挺爽”等自然口吻，但不要八条都用同一句口头禅；不装成亲身体验，不为了显得随意而故意写错字。

- **Telegram**：保留完整标题、真实夸克链接、2～8 个相关标签和 X／频道双入口。正文采用自然短段落，具体讲钩子、来源支持的用处或做法；段落数量按内容决定，不套固定结构。商业题材讲清做什么、面向谁、成交和交付路径。正文连同标记不超过 1024 字符，HTML 必须有效。可以使用 0～2 个有语义作用的 emoji，长短句和段落节奏自然变化。
- **X**：按 [X 文案风格池与批次去重](x-copy-style-pool.md) 选择适合题材的主风格。用一个明确主卖点组织文案，并可把来源支持的相关好处、步骤或具体烦恼讲透；围绕这个用处，把来源支持的相关重要优势讲完整；不堆不相关的目录和泛泛介绍。数字人可以讲不用真人露脸和反复拍摄，以及商品口播怎样持续介绍产品；工具可以讲文字转配音、改稿免重录；商业项目可以讲清做什么、谁付钱和成交交付路径。成人两性内容可直白但不露骨，聚焦性知识、双方感受与沟通，不许承诺疗效或“变大师”。
- **语气和版式**：允许短句、长句、自然换行、不同段落数和 0～2 个 emoji。不要机械地每句单独成行，不要每段强加句号，也不要让八条只有标签不同、说话方式完全相同。口语自然度与标签多样性都要过审。
- **链接**：X 正文最后一行必须是原始完整夸克 URL，且全文只出现这一个链接一次；链接前留一个空行。不得加“资料在这”“放这了”“去看这套课”“值得收藏”等行动号召，不加 Telegram 尾句，不给 URL 加“资料／课程”等前缀。原始 URL 必须逐字保持一致。

不得编造亲身使用、赚钱或效果；收益金额、销量、时长、数量和转化效果只用能从来源核实的数字，不把案例数字说成普遍结果。不必在每篇正文机械声明“收入未证实”；当来源证据不足时，应先继续查看来源或收窄主张，并在 `copy-review.json` 记录限制。药方等安全事实如不能自行使用，可在正文自然简短说明。

### 已认可的表达参考

参考说话方式，不将例子的产品功能或效果搬到其他条目，不让八条重复相同结构。配音工具在来源已确认支持文字转语音、参考音色和导出时，可以这样讲：

> 我靠，现在配音已经变成“复制、粘贴、生成”了 😂
>
> 写好的稿子丢进 Yovoice，一条旁白就出来了，听着合适直接导出
>
> 想用自己的音色，放一小段自己的录音进去也行。后面文案改了，就改文字重新生成，终于不用一句话念八遍了
>
> 做视频本来就够折腾，配音这一步能这么省事，真挺爽的

实际成稿还要空一行，再放该行原始完整 URL。数字人可以从“人都去睡觉了，卖货的视频还在，这个才有意思 💸”展开不用露脸、免反复真人拍摄、已发布商品视频持续展示和商品成交路径；短视频资料不支持改写成“24 小时全自动直播赚钱已经实现”。成人两性可从“性知识这东西，真别觉得自己早就毕业了 😏”展开双方感受和沟通，不补写露骨操作或效果保证。

## 3. 记录、回读和批次执行

1. `doctor` 与 Telegram 只读连接检查通过后，使用明确的真实 Excel 行号运行不带 `--telegram-send` 的 `python scripts/run_workflow.py publish --limit 8 --row-number ROW1 ...`。这一步只准备媒体和待审初稿；记录各行成功或失败，不发送 Telegram，也不创建 Typefully 草稿。
2. 对准备成功的每条读取完整目录和必要的真实预览，手工改写 `telegram-caption.html` 与 `x.txt`，删除 `【待审初稿】`。原始链接逐字保持一致。不要把旧模板直接当成审阅通过。
3. 改写后逐条运行 `.venv/bin/python .codex/skills/telegram-auto-publish/scripts/review_copy.py record --row-index 序号 --row-number 真实Excel行号 --category tool --style-label '痛点＋判断型' --angle '具体主卖点' --key-phrase '两个渠道共有的关键短语' --source-note '来源怎样支持主卖点和相关好处' --evidence '完整目录中的真实文件名'`。共同短语选择至少三个字符的明确产品名或用途，不为过检把冗长 ZIP 文件名硬塞进正文。商业项目填写 `--category commercial`、`--offer`、`--audience`、`--revenue`、`--support supported|partial|unclear`。`--evidence` 可重复，每个值必须与 `items` 中的文件名或路径完全一致。凡资料涉及接单、成交、带货、稿费等商业路径都按商业项目审阅。证据边界写进 `source_note`，不要求在正文重复声明。
4. 每条记录成功后用同一脚本 `check --row-index 序号 --row-number 真实Excel行号` 回读，检查来源、事实、自然口吻、真实链接、X 末行 URL 唯一性、HTML、风格标签、开头和版式分布。修改正文后重新 `record`，确保哈希对应最终文件；Excel 简介改动后也重新审阅。
5. 批次硬门保持不变：八条至少 6 种不同 X 主风格、至少 3 种版式；相邻风格和开头不得重复，前十个可见字符不得重复。还要判断同风格文案是否真的自然、有变化，不能只换标签或开头词凑数。媒体准备失败的行单独记录并留待恢复，不放入发送子集。其余准备成功的行全部审阅通过后，才对原选中行号子集运行带 `--telegram-send` 的发布命令。发送入口核验发送子集审阅记录和文件哈希，任何缺失、过期、旧模板或链接错误都须在第一条发送前阻断。

任一准备成功的行未通过审阅，本次不得外发、不得推进 `next_serial`，也不得为失败行创建 Typefully 草稿。修好后沿用原行号继续。已有 Telegram 消息 ID、已发送或发送中的记录先按幂等规则核对，不重发。Telegram 成功后，Typefully 上传的 `x.txt` 必须与审阅记录一致，建稿后回读同一草稿 ID。

## 4. Typefully 后续排期

Typefully 建稿并回读到 `draft` 只表示草稿已建立，不表示每日任务完成。建稿后必须按 [Typefully 浏览器排期与状态回读](typefully-browser-schedule.md) 完成排期操作，并通过 GET 回读确认状态为 `scheduled`；只有排期成功且读回状态匹配，才算本条 X 任务完成。排期失败或状态不符时如实记录并停止该条，不把 `draft` 说成已排期。
